# Warscythe reader: published 3.2.2 API audit

Verified 2026-11-21. Research only: no installation, app changes, prototype, commit, or deployment. **Recommendation: use the library as an optional presentation over the archive's canonical structured prose, behind a plain reading view. Begin with button-driven page turns and selectable text. Gesture turning is a separate, unproved enhancement.**

## Integration contract

Use the default `HTMLFlipBook` export (named export also exists). `width` and `height` are required positive CSS-pixel page dimensions. Each direct page child should be a stable keyed host `<div>` containing a semantic prose wrapper. A custom page component must forward its ref to an actual `HTMLElement`; a missing node produces `DETACHED_PAGE`. Keep typography, padding, backgrounds and overflow treatment inside that wrapper: the engine owns root geometry, transforms, clipping, stacking and paper paint. Set paper via `pageBackground`. Memoize page elements by book/content version; keep counters and transient animation state outside them. [Published React implementation](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/packages/react/src/HTMLFlipBook.tsx), [React types](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/packages/react/src/types.ts).

The engine consumes **already separated HTML leaves**. It exposes no prose pagination/reflow API. Keep canonical chapters/paragraphs independent of visual leaves; use short authored pages for the bounded first implementation. Do not silently clip overflowing prose. Search/filter the canonical data, not the currently visible DOM; hidden and lazy leaves are unavailable to normal browser find. A plain chapter view is the escape for long text, large fonts and full-document search. This architecture is an implementation recommendation derived from the published HTML-loading API and visibility rules. [Core facade](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/packages/core/src/PageFlip.ts), [styles](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/packages/core/src/styles.ts).

### Controls and events

- `ref: FlipBookHandle` provides `flipNext(corner?)`, `flipPrev(corner?)`, `flipToPage(n)`, `turnToPage(n)`, `cancelTurn()`, `destroy()` and `pageFlip()`. Turn/cancel methods return booleans; `pageFlip()` returns core `PageFlip | null`. Queries such as `canTurn('next')`, `getVisiblePages()` and `getPageCount()` belong on core, not the handle. Prefer the supplied `usePageFlip(initialPage)` hook for its ref, actions, `bookProps`, `canGoNext`, `canGoPrev`, `visiblePages`, count and orientation. Do not calculate boundaries as `page < count - 1`: navigation is by spreads. [Handle and hook types](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/packages/react/src/types.ts), [hook implementation](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/packages/react/src/usePageFlip.ts).
- React callbacks receive **unwrapped payloads**, unlike core's `{ data, object }` event wrapper. `onLoaded`, `onReady`, `onPagesChanged` and `onPageChange` receive `{page, pageCount, orientation, visiblePages}`; `page` is the zero-based spread head. Seed chrome on `onLoaded`: mount does not emit a page change. Orientation/state callbacks receive `{orientation}` / `{state}`. `onTurnRejected` includes `reason`, nullable `direction`, `targetPage`, `landedOn`, and optional `code`. Treat refusals as outcomes, not successful navigation. [Event definitions](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/packages/core/src/Event/EventObject.ts).
- For resume/deep links, freeze `initialPage` at mount. Updating it remounts the engine. Alternatively use controlled `page` **with** `onPageChange`; without the callback it snaps back to the prop. `pageTransition="instant"` suits deep links. Keep chapter identity separate from leaf index. [React implementation](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/packages/react/src/HTMLFlipBook.tsx).
- Render labeled real Previous/Next buttons. Built-in `controls="auto"` reveals its hidden controls on focus; `"visible"` shows them; `"none"` is suitable only when providing equivalent controls. Keyboard defaults on, handles unmodified arrows/Home/End when the book or its own controls owns focus, and preserves descendant shortcuts. The root is a `group`, not `application`. [React implementation](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/packages/react/src/HTMLFlipBook.tsx).

### Responsive sizing, selection and motion

Use `sizing="responsive"`, `usePortrait`, meaningful width/height bounds and a measurable container. Portrait activates when container width is below `2 * minWidth`; it is **not** a device-orientation flag. The engine fits the declared aspect ratio within width/height caps. `ResizeObserver` and `visualViewport` drive updates; changing live width/height does not require a React key. `hardCovers`, `initialPage`, and `injectStyles` do remount. Do not rotate/skew the book or its ancestors: supported hit testing only handles translation/scale. [Settings](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/packages/core/src/Settings.ts), [bounds computation](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/packages/core/src/Render/Render.ts), [accepted limitations](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/docs/KNOWN-LIMITATIONS.md).

**Critical text-reader trap:** `flipOnClick="never"` still permits drag turns. `respectInteractiveContent` protects links/buttons/inputs and specified media, **not prose**. Even `pointerInput={[]}` leaves the library's `.stf__block` stylesheet disabling text selection and iOS callouts. The baseline should therefore set `pointerInput={[]}`, `flipOnClick="never"`, `foldCornerOnHover={false}`, `respectInteractiveContent`, `allowTouchScroll`, and explicitly override scoped block/prose `user-select:text`, `-webkit-user-select:text`, `-webkit-touch-callout:default`. Preserve native touch/zoom behavior; verify before adding overrides. Core always prevents `dragstart`, including with pointer turning disabled: selecting/copying text can work after the CSS override, while dragging a selected excerpt remains suppressed. This still requires browser proof. Do not invent fake `role="button"`/`contenteditable` prose to bypass hit testing. [Exact UI pointer gating](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/packages/core/src/UI/UI.ts), [CSS](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/packages/core/src/styles.ts), [interactive selector](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/packages/core/src/interactive.ts).

Keep `respectReducedMotion={true}` (default). It checks the media query when computing animation duration, yielding an instant turn. It does **not** disable direct pointer folding or guarantee cancellation when the preference changes mid-turn. Button-only navigation avoids that gap. Host transitions also need their reduced-motion rules. `onTurnProgress` is silent for instant turns/hover, and has no guaranteed terminal 1 or cancellation 0; settle UI from `onPageChange` / `onChangeState`. [Reduced-motion implementation](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/packages/core/src/reducedMotion.ts), [fold implementation](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/packages/core/src/Flip/Flip.ts), [progress limits](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/docs/KNOWN-LIMITATIONS.md).

## Cleanup, fallback and release gates

The published wrapper constructs in an effect, portals leaves into the engine block and destroys on cleanup; indexed refs explicitly account for Strict Mode replay. Core removes pointer/viewport listeners, disconnects its observer and stops rendering on destroy. **Source inspection is not a passing React 19 Strict Mode test.** Use normal conditional unmount for leaving the reader. Avoid a second host-created `PageFlip`; avoid manually destroying through `pageFlip()?.destroy()`. If explicitly retiring while mounted, use handle `destroy()`. [Wrapper cleanup](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/packages/react/src/HTMLFlipBook.tsx), [core cleanup](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/packages/core/src/PageFlip.ts), [UI cleanup](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/packages/core/src/UI/UI.ts).

Recommended wrapper: lazy-load the book adapter on opening a work; keep canonical content and selected chapter outside it; use stable page children and one hook/ref; supply own controls and selectable prose; key only on work/content version. Wrap loading/rendering in an error boundary with a visible **Read as text** switch that renders the same content and preserves chapter position. Guard imperative navigation errors separately: [an error boundary does not catch event-handler exceptions](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary). If the engine cannot initialize, the plain reader remains usable. Observe no real load, overflow, or repeated errors as a failed POC rather than adding patches inside the engine.

Required runtime evidence before promoting the adapter:

1. Production build and measured incremental reader chunk; React 19 Strict Mode mount → turn → unmount/reopen loops, book changes, no duplicate shells/errors, no continuing callbacks after removal.
2. Desktop spread and 320/390px portrait; first/last/odd-leaf boundaries, Previous/Next, chapter jump, live resize during a curl, font-loading/200% text and long-prose overflow checks.
3. Drag-selection/copy without turning, long-press selection, links, vertical scroll and pinch zoom; keyboard focus and screen-reader announcement check; native `prefers-reduced-motion` emulation with instant navigation.
4. Forced module/render failure and explicit plain-view switching preserve readable content and chapter. Search finds canonical text outside the mounted leaf window.
5. Real iPhone/iPad and Android browser checks before claiming physical-device compatibility. Upstream reports Chromium/WebKit automation; physical iOS, Android WebView and Firefox are not all signed off. Portrait clones are static, inert, aria-hidden copies retaining IDs; avoid dynamic page mutations mid-turn. `lazyRadius` only windows React leaf contents, not archive data or the number of leaf roots. [Browser support](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/README.md), [live face contract](https://github.com/gul-labs/flipbook/blob/b436092f325bf01f5bc80255f5b720e492f121aa/docs/LIVE-PAGE-FACES.md).
