# Warscythe book and letter reader research

Research snapshot: 21 November 2026. Scope: research only. No skill or package installed; no prototype, application change, commit, or deployment. Official source, license files, live npm metadata and GitHub commit metadata were read. Library demonstrations, benchmark claims and accessibility claims were **not independently browser-tested**.

## Decision

**Recommend one isolated proof of concept with `@gullabs/react-flipbook@3.2.2`, before choosing a production library.** Its published React peers include React 19, its published JavaScript contains keyboard/status controls and reduced-motion support, and repository activity is recent. Those are concrete advantages over the original wrapper; they do not prove the reader meets Warscythe's requirements. Its engine is MPL-2.0, so this choice carries source/notice obligations on distribution. The hardest unresolved requirement is selecting and reading text without accidentally turning a page. If that fails, reject the candidate before designing the full library.

This recommendation is for **collected codex spreads**. A single folded letter should keep its own open/unfold/read interaction and selectable transcription. A spine-bound curl engine does not establish that it can unfold a loose sheet. Existing Framer Motion may be sufficient for that separate interaction; that is a design inference, not a tested implementation.

### Original engine: the issues are relevant to this app

The [original UI source](https://github.com/Nodlik/StPageFlip/blob/master/src/UI/UI.ts) binds book-wide mouse/touch handling and calls `preventDefault()` on qualifying mousedown. `disableFlipByClick` does not establish selection-friendly drag behavior. Its [settings source](https://github.com/Nodlik/StPageFlip/blob/master/src/Settings.ts) rejects `flippingTime <= 0`; use the documented instant `turnToPage` family for an application-owned reduced-motion path rather than setting duration to zero.

The [render source](https://github.com/Nodlik/StPageFlip/blob/master/src/Render/Render.ts) schedules a recurring animation-frame loop; [destroy](https://github.com/Nodlik/StPageFlip/blob/master/src/PageFlip.ts) removes UI/root without cancelling that loop. [Issue 71](https://github.com/Nodlik/StPageFlip/issues/71) reports the same defect. The source confirms a reason to test repeated route entry/exit; no performance measurement was run here. The [React wrapper source](https://github.com/Nodlik/react-pageflip/blob/master/src/html-flip-book/index.tsx) also lacks an engine-destruction effect cleanup.

- Turn.js public [third-release license](https://github.com/blasten/turn.js/blob/master/license.txt) is explicitly noncommercial. Their published domain allowances/pricing are inconsistent, so final edition, grant and terms need confirmation if revisited. Do not take an npm mirror's license field as permission for a different edition.
- GulLabs has [per-package licensing](https://github.com/gul-labs/flipbook/blob/main/LICENSE): React MIT, engine [MPL-2.0](https://github.com/gul-labs/flipbook/blob/main/packages/core/LICENSE). MPL sections 3.1–3.3 require covered source and notices to remain available under its terms when distributing covered executable code, while permitting a larger work under other terms. The repository explicitly includes serving bundled JavaScript to browsers in its distribution guidance. This does not mean all Warscythe source must become MPL. Preserve the engine's corresponding source and provide the required notice/source access before a public release.

### Why the fork is only a candidate

GulLabs documents [keyboard, live region, labeled controls and reduced-motion options](https://github.com/gul-labs/flipbook#accessibility). Read-only inspection of the published [React bundle](https://cdn.jsdelivr.net/npm/@gullabs/react-flipbook@3.2.2/dist/index.js) found Arrow-key and live-region code; the published [core bundle](https://cdn.jsdelivr.net/npm/@gullabs/flipbook-core@3.2.2/dist/index.js) contains `prefers-reduced-motion` handling. No code was executed.

Current [source](https://github.com/gul-labs/flipbook/blob/main/packages/react/src/HTMLFlipBook.tsx) manages hidden-page focus and `inert`; [known limitations](https://github.com/gul-labs/flipbook/blob/main/docs/KNOWN-LIMITATIONS.md) say curl faces use cloned snapshots and rotated/skewed ancestors break pointer hit-testing. These are reasons to keep the book unrotated and test hidden/duplicate content with assistive technology. Do not equate an accessibility options list, source comments or upstream CI with an independently accessible Warscythe reader. No automatic prose pagination, readable overflow strategy or loose-letter unfolding was verified in any candidate.

## Exact next validation / Definition of Done for the proof of concept

Use only a small representative codex: cover, short prose, long prose, a damaged/handwritten original with transcription, a link/button, and an end page. No full lore migration until this passes.

1. **Dependency gate:** inspect Warscythe's actual React/React DOM/Node versions; resolve the pinned candidate and core without force/legacy-peer flags; run the normal app build. Record the exact versions. The real application package was not re-audited in this research task.
2. **Readable content:** actual HTML words, selection and copy/paste on desktop and touch; readable line lengths at 320/390px, 768px and laptop width; no clipping after font load or 200% zoom. Decide authored pagination versus a scrolling transcription instead of shrinking long lore to fit.
3. **Gesture gate:** ordinary vertical reading/scrolling, long press, selection handles, pinch zoom and clicking nested links must not turn a leaf. Deliberate edge drag/turn controls must work both directions, including cancelled gestures. If the engine cannot isolate edge turning without selection loss, stop and reject it.
4. **Responsive state:** phone single-page, tablet/laptop spread; resize and rotate while mid-book without losing position, blank leaves or incorrect page numbers. Test actual iOS Safari and Android Chrome when available; emulation alone does not prove their touch behavior.
5. **Accessible alternative:** visible labeled Previous/Next controls; keyboard navigation without hijacking text inputs; correct focus after turns; sensible current-page announcements; hidden pages/clones excluded from the reading order. Test with a screen reader. Provide a plain reading/transcription mode from the same content.
6. **Motion:** OS reduced-motion preference before mount and changed during the session; instant navigation with no hover curl/autoturn/audio surprises. Verify page text remains available through the alternative view.
7. **Lifecycle/regression:** React Strict Mode, repeated entry/exit, replacement of documents, first/last page and deep-link reload; record console/errors and confirm no accumulating animation loop/listeners. Preserve and recheck current lore navigation and app routes.
8. **Letter check:** separately demonstrate one loose sheet opening/unfolding, readable native transcription and an instant reduced-motion alternative. Do not claim a codex turn proves this interaction.

Close the experiment with screenshots/replay, environment/version record, pass/fail table and known limitations. Until then, “realistic,” “mobile compatible,” “React 19 ready” and “accessible” remain vendor claims or bounded source evidence—not a finished reader. Build → measure → verify → close, then expand.
